# Pulse Arbitrage Agent — исправление v0.9.3

Это обновление исходного кода мобильной облачной версии. Это **не готовый опубликованный сайт** и не Windows EXE. Исправленные файлы нужно загрузить в исходный репозиторий и выполнить повторное развёртывание.

## Исправления

- У прибыльных позиций отсутствие прямой ссылки на BUFF или Market больше не означает автоматическое удаление из списка. Интерфейс может показывать поиск предмета по названию вместо прямой ссылки.
- Время обновления старше 2 часов теперь отображается как предупреждение, а не как скрытый финансовый фильтр. Перед покупкой следует самостоятельно подтвердить актуальные цены.
- Совпадение названий между BUFF и Market учитывает разницу в регистре букв, повторяющихся пробелах и неразрывных пробелах. Важные различия (название, состояние предмета и иные характеристики) сохраняются.
- Повторяющиеся записи каталога не удаляют друг друга: используется запись с более свежим временем обновления.
- Если нет статистики средней цены за 30 дней, оценка строится по текущему минимальному предложению и показывается предупреждение. Отсутствующие продажи за 30 дней по-прежнему не позволяют пройти фильтр.
- Убрана **вторая скрытая фильтрация** в `finalizeVisible()`, которая снова отбрасывала всё без прямой ссылки.
- В интерфейсе появились счётчики: BUFF, Market, совпадения, без пары, есть цены, прошло порог себестоимости, достаточно продаж, прошло ROI, показано; а также статистика исключений.
- Добавлена кнопка **«Проверка API — до 8 токенов»** (до 4 запросов BaseInfos по опубликованной стоимости 2 токена каждый). Она не включает мониторинг, Telegram или дорогостоящую проверку истории. Актуальные тарифы следует сверять в Pulse.

## Финансовые фильтры не изменены

- Курс: 13,07 ₽ за ¥
- Коэффициент чистой выручки: 0,9025
- Минимальная себестоимость: 500 ₽
- ROI: от 10%
- Продаж за 30 дней: от 40
- Нулевая или отрицательная прибыль всегда исключается.

## Как применить на телефоне

1. Открой свой приватный репозиторий GitHub с исходниками мобильного агента.
2. Замени как минимум `main.go`, `pulse_live.go` и `ui.html` файлами из этого архива. Для тестов также добавь `regression_093_test.go`.
3. Сделай commit изменений. Если Render привязан к этому репозиторию, проверь, что выполнилось новое развёртывание.
4. Убедись, что `PULSE_API_KEY` хранится **только** в защищённых переменных Render. Никогда не загружай ключ в GitHub.
5. Останови периодический мониторинг, если он включён. В веб-интерфейсе нажми «Проверка API — до 8 токенов», затем посмотри новые диагностические счётчики.
6. Если `Совпало = 0`, проблема сопоставления или охвата страниц. Если `Совпало > 0`, а `Есть цены = 0`, проблема числовых полей API. Если `ROI прошёл = 0`, проверь количество продаж и доходность.
7. Для первого теста отключи необязательную «Строгую проверку историей Market». Эта проверка может отдельно скрыть все предварительные результаты при недоступности публичной истории.

## Что реально проверено

- `go test` пройден многократно, включая **три отдельных мок-сканирования** с различиями регистра и пробелов, пустыми ссылками, старыми датами, низким объёмом продаж и отрицательной прибылью.
- JavaScript прошёл синтаксическую проверку `node --check`.
- Облачный локальный сервер прошёл тест запроса страницы с паролем и запроса `/api/result`.
- **Никакие запросы к реальному Pulse API не выполнялись и никакие токены не списывались**: секретный API-ключ не доступен в этой рабочей среде.

Данные и результаты на настоящем аккаунте требуют отдельной проверки. Положительная расчетная прибыль не гарантирует продажу по выбранной цене.
